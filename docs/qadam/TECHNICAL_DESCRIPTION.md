# TECHNICAL DESCRIPTION — QADAM Growth OS

Описание системы для читателя, который её не писал: что это, из чего собрано, какие
инварианты держит и чем они доказаны.

---

## 1. Что это

AI-маркетолог для малого офлайн-бизнеса в Казахстане. Продукт превращает наблюдаемое
отклонение в выручке в одно конкретное действие, которое владелец может подтвердить за один
шаг, — и показывает, что из этого вышло, не путая влияние с приростом.

Центральная сущность — **Growth Contract**: пакет из аудитории, оффера, экономики, лимитов,
правила остановки и способа измерения. При подтверждении он замораживается вместе со
снимком и хешем, поэтому вопрос «что именно я одобрил три недели назад» имеет однозначный
ответ.

## 2. Из чего собрано

| Слой | Технология | Роль |
|---|---|---|
| Интерфейс | Next.js 16 (App Router), React 19, Tailwind | Server components по умолчанию; клиентские — только там, где нужна интерактивность |
| Действия | Server Actions | Мутации через формы, работающие и без JavaScript |
| Данные | Supabase Postgres 17 | 80 таблиц, из них 67 тенантных, RLS на всех |
| Авторизация | Supabase Auth + `@supabase/ssr` | Сессия в cookie, проверяется в прокси и повторно в базе |
| Домен | TypeScript, целочисленная арифметика | Margin Shield, симулятор, entitlements — детерминированы |
| AI | Провайдер-независимый интерфейс | По умолчанию отключён; детерминированный шаблон — поддерживаемое состояние |
| Тесты | node:test, pgTAP, Playwright, axe-core | 676 автоматических проверок |

Приблизительных числовых типов (`double precision`, `real`) в схеме нет: деньги считаются в
минорных единицах целыми числами. Для тенге минорная единица — сам тенге, деления на 100 нет.

## 3. Как устроен доступ

Три независимых рубежа. Скрытая ссылка в навигации рубежом не считается.

```
запрос → прокси            проверяет сессию и платформенную роль на каждом рендере
       → server action     проверяет повторно, с тем набором ролей, который нужен именно ей
       → RLS в Postgres    проверяет в третий раз, на каждой таблице
```

Прямой URL, закладка и сценарный POST проходят через все три. Платформенная роль читается из
приватной таблицы `private.platform_admin_assignments`; `user_metadata` не используется, и
это проверяется чтением тела функции в pgTAP.

**Привилегии, которые RLS не фильтрует, отозваны.** `TRUNCATE`, `TRIGGER` и `REFERENCES`
изъяты у `anon` и `authenticated`: политики строк для них не действуют, и до исправления
владелец одного арендатора мог уничтожить данные всех.

**Поверхность Data API объявлена явно.** Все 79 таблиц имеют собственные гранты, а не
наследуют автоматические, которые платформа переводит в opt-in.

## 4. Инварианты и чем они держатся

Каждый — правилом в базе, а не соглашением в коде.

| Инвариант | Механизм |
|---|---|
| Строку нельзя перенести в другой тенант | Триггер `prevent_business_id_change` на каждой тенантной таблице |
| Смоделированный результат не станет фактом | CHECK-ограничение: `is_mock` и `verified_fact` несовместимы |
| Канал не станет подключённым без доказательства | CHECK требует непустой `last_health_check_at` для `connected` |
| Опубликованную версию шаблона нельзя изменить | Триггер `protect_published_template_version` |
| Аудит администратора нельзя переписать | Триггер отклоняет UPDATE и DELETE на `admin_audit_log` |
| Действие администратора без причины не происходит | `admin_audit` отказывает при причине короче трёх символов |
| Последнего владельца нельзя убрать | Триггер `guard_last_owner`, обход только через `transfer_ownership` |
| Запись каталога с историей нельзя удалить | Триггер `guard_catalog_delete` |
| Отправка без действующего согласия невозможна | `send_gate` проверяет заново в момент отправки, не при сборке аудитории |
| Согласие с более поздним ответом побеждает | `latest_consent_is_granted` берёт `bool_and` по самой свежей метке времени |
| Одно событие обрабатывается один раз | Уникальность `(business, provider, external_event_id)` и ключи идемпотентности |
| Одобренный контракт неизменен | `accepted_snapshot` + `content_hash`, проверка версии при переходе |

## 5. Экономика

Симулятор и Margin Shield живут на сервере и работают в целых минорных единицах. Модель не
участвует: она предлагает механику и пишет тексты, но решение о марже принимает сервер.

Заблокированное решение нельзя записать как одобренное — проверено попыткой вставки напрямую
в базу.

Impact Ledger различает пять видов чисел и никогда их не складывает:

| Вид | Что означает |
|---|---|
| `forecast` | прогноз до запуска |
| `influenced` | выручка тех, кто получил сообщение — **не заслуга кампании** |
| `incremental_estimate` | оценка прироста относительно baseline |
| `mock_actual` | смоделированный результат в демо-режиме |
| `verified_fact` | подтверждённый факт — **невозможен, пока нет подключённого источника** |

## 6. AI

Провайдер по умолчанию не задан, и это поддерживаемое состояние: продукт работает на
встроенном детерминированном шаблоне и прямо пишет владельцу, что текст собран шаблоном.

При подключённом провайдере действует тот же контракт: редакция PII перед отправкой,
нейтрализация попыток инъекции, строгая проверка схемы ответа, потолок стоимости и времени,
ограниченное число повторов, детерминированный откат при любой ошибке. В провайдер уходит
только хеш входа — в базе хранится `input_hash` длиной 64 hex, что проверяется CHECK.

Модель не может: изменить цену, бюджет или аудиторию; обойти Margin Shield; отправить
сообщение; создать `verified_fact`.

## 7. Исполнение

Отправка идёт через outbox: лизинг батча `FOR UPDATE SKIP LOCKED`, отсечки повторов
30/60/120/240 секунд, затем dead letter. Внутри транзакции HTTP-вызовов нет.

Аварийная остановка выключает исходящий поток целиком и записывает, кто её нажал, когда и
почему. `send_gate` проверяет по порядку: аварийная остановка → активность бизнеса →
список подавления → согласие → тихие часы → дневной лимит → частотный лимит.

Планировщика платформы нет: цикл запускает внешний вызов `/api/jobs/run-cycle` с секретом,
сравниваемым в постоянном времени, с защитой от повтора по ключу цикла и rate limit.

## 8. Локализация

Локаль определяется на сервере до первого рендера: cookie → сохранённая локаль пользователя
→ `Accept-Language` → русский. Cookie, а не `localStorage`, именно затем, чтобы сервер мог
её прочитать.

Сообщения принимают именованные параметры, а не склеиваются из кусков; формы множественного
числа берутся из `Intl.PluralRules` — в русском их три, и самодельная проверка `n === 1`
молча давала бы неправильный русский. Домен не импортирует реестр локализации: расчёты идут
в минорных единицах, форматирование — только на уровне представления.

Оболочка кабинета, лендинг, авторизация и тарифы двуязычны. Тексты внутри экранов кабинета
остаются русскими, и интерфейс сообщает об этом на казахском — вместо того чтобы молча
показать русский под казахской навигацией.

## 9. Приватность

Контакт клиента хранится как необратимый хеш для поиска и маска для узнавания. **Колонки,
куда можно было бы положить адрес, в схеме нет** — это сильнее, чем обещание её не заполнять.

Согласия раздельные: участие в программе лояльности и маркетинг — разные записи, и внутри
маркетинга зонт `marketing` применяется только к каналам, по которым нет отдельного ответа.
Отзыв сохраняется как доказательство.

Удаление реализовано как анонимизация там, где закон требует сохранить запись: суммы
остаются, человек исчезает. Страница `/privacy` генерируется из таблиц `data_inventory` и
`retention_policies`, поэтому не может разойтись со схемой, и сама сообщает, что юрист её не
проверял.

Платформенная аналитика агрегатная и скрывает срез, в котором меньше пяти бизнесов.

## 11. Границы

Продукт не отправил ни одного сообщения, не принял ни одного платежа и не работал под
реальным трафиком. Нагрузка измерена на одном локальном процессе. Полный список ограничений
— в [KNOWN_LIMITATIONS](KNOWN_LIMITATIONS.md), и он не сокращён для красоты.
