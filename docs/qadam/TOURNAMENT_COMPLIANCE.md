# Соответствие положению SERPIN Business Tournament

Источник: `SERPIN_Business_Tournament.pdf` (5 страниц). Сверка: 2026-08-03, против
развёрнутого стенда `https://qadam-growth-os.vercel.app` и коммита в `master`.

Документ отвечает на один вопрос: где в продукте лежит каждый обязательный пункт
положения и чем доказано, что он работает. Там, где пункт закрыт частично, так и
написано — оценка, завышенная в собственном документе, стоит дороже пропуска.

---

## 1. Обязательные функции платформы

| Пункт положения | Где в продукте | Доказательство |
|---|---|---|
| Главная объясняет, что это и для кого | `/` — герой, «Как работает», «Для бизнеса» | `tests/a11y/audit.mjs`, ручной обход |
| Ценностное предложение: клиенты, продажи, автоматизация | `/` — секции Impact Ledger, Margin Shield, автоматизации | там же |
| CTA «Найти клиентов», «Создать акцию», «Начать использовать платформу» | герой + финальный блок; ведут в `/signup?intent=…` и `/demo` | E2E `owner` — переход и результат |
| Карточки инструментов: название, описание, тип, «Активировать»/«Использовать» | `/app/tools` | E2E `owner`: активация меняет строку `business_tools` и добавляет инструмент на «Сегодня» |
| Фильтры: маркетинг, продажи, удержание, аналитика, автоматизация | `/app/tools` — пять категорий + «Рекомендуемые» | E2E `owner` |
| «Сохранить в избранное» | `/app/tools` — сердце на карточке, вкладка «Избранное» | E2E `owner`: состояние переживает перезагрузку |
| 2–3 ключевых модуля с пошаговым интерфейсом | Студия кампаний (7 шагов), Клиентская база и сегменты, Аналитика и Impact Ledger, Контент-студия, Лояльность | E2E `owner` (60 проверок) и `customer` (36) |
| Тестовые акции: скидка, бонусы, купоны | Студия, шаг 3: шесть механик (2+1, подарок от суммы, купон возврата, фикс. скидка, процент, баллы) | E2E `owner`: контракт собирается и утверждается |
| Симуляция роста клиентов | Студия, шаг 5: осторожный / базовый / оптимистичный сценарий | `src/domain/simulator.ts` + unit-тесты |
| Метрики: новые клиенты, повторные покупки, эффективность акции | `/app/analytics` — 12 KPI + 4 дашборда | E2E `growth`: доли состава базы сходятся с числом гостей в базе |
| Личный кабинет: активные инструменты и акции | `/app/today` | E2E `owner` |
| Личный кабинет: базовая статистика | `/app/today`, `/app/analytics` | E2E `owner` |
| Личный кабинет: **история действий** | `/app/journal` — единый журнал с человеческими формулировками | читает `activity_logs`; коды переводятся `src/domain/activity-log.ts` |
| Личный кабинет: рекомендации по улучшению | `/app/recommendations`, «Сегодня» | цикл исполнения собирает их из сигналов; расписание внешнее и best-effort, см. KNOWN_LIMITATIONS |
| Регистрация собирает тип, размер и цели | `/onboarding` — 6 шагов | E2E `owner` |
| **Рекомендации инструментов по профилю** | `/app/tools` — блок «С чего начать именно вам» + механики под тип заведения | `src/domain/tool-recommendations.ts`, 7 unit-тестов |
| Пример: кофейне 2+1 и лояльность, салону — повторный визит | тот же блок: механика зависит от типа и ведёт в студию с предзаполненным полем | unit-тест «механики отличаются по типу» |
| Админ: добавлять, редактировать, удалять инструменты и шаблоны | `/admin/tools`, `/admin/templates` | E2E `admin` (45 проверок) |
| Админ: управлять категориями и типами бизнеса | `/admin/categories` | E2E `admin` |
| Админ: аналитика использования (активные бизнесы, популярные инструменты) | `/admin` — карточки платформы и рейтинг активаций | E2E `admin` |

## 2. Технические требования

| Требование | Как выполнено |
|---|---|
| Кликабельный интерфейс с навигацией | Next.js 16 App Router, 17 разделов кабинета, админка, публичный сайт, Telegram Mini App |
| Ключевая функциональность через интерактивные элементы | Server Actions; формы работают и без JavaScript |
| Структурированные данные или БД | Supabase Postgres 17, 80+ таблиц, RLS на всех тенантных |
| Логичный путь: от входа до ключевой функции | вход → «Сегодня» → сигнал → рекомендация → студия → контракт → запуск → Impact Ledger |
| Доступен онлайн по ссылке | https://qadam-growth-os.vercel.app (демо-вход на странице `/demo`) |
| Дополнительно: AI | провайдер-нейтральный слой (Gemini или встроенный демо-провайдер); каждый прогон записан в `ai_generation_runs` с провайдером, моделью и источником. На стенде сейчас `provider='demo'`, `model='qadam-demo-answers-v1'` — это видно в журнале генераций, а не спрятано |
| Mock-данные допустимы | DEMO DATA помечены на каждом экране; разделение демо/боевого режима держится проверкой в базе, а не соглашением |

| Модульные (`npm run test`) | 167/167 |

Четыре несовпадения в наборе безопасности — это «правильный секрет принимается»
и «правильно подписанное событие принимается». Локальная копия
`QADAM_JOB_SECRET` и `QADAM_WEBHOOK_SECRET` разошлась с тем, что стоит на
Vercel; сам продукт отказывает всему неавторизованному верно (эти проверки
проходят), а что верный секрет принимается — видно по успешным прогонам
`execution-cycle.yml` в GitHub Actions.

## 5. Честные слабые места

1. **Kaspi отвечает 429 с адресов Vercel.** Живой поиск цен на стенде отказывает, и
   экран об этом говорит. Цены в демо собраны тем же кодом с локальной машины.
2. **hh.kz отвечает 403** на любой User-Agent из развёртывания. Вилка зарплат не
   выдумывается: раздел показывает отказ площадки.
3. **Казахские тексты не проверены носителем.** Машинную естественность казахского
   продукт не гарантирует и говорит об этом на экране генерации.
4. **Прирост (incremental) измеряется только там, где зафиксирована базовая линия.**
   Где её нет — стоит «—», а не оптимистичное число.
