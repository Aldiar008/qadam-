## 5. Разделение режимов

Проверено не чтением кода, а сборкой и запуском **второго сервера** в PRODUCTION_MODE
(27/27):

| Требование | DEMO_MODE | PRODUCTION_MODE |
|---|---|---|
| Кнопка demo-входа | есть | **нет** |
| Маршрут `/demo` | открывается | редирект `?message=demo_disabled` |
| Скачок во времени | предлагается | **не предлагается** |
| DEMO-бейдж на экранах кабинета | виден на всех проверенных | — |
| Подключённые каналы | 0 | 0 |
| Ненастроенная интеграция | — | пишет «не подключено» |
| Биллинг | — | «платёжный провайдер не подключён» |
| Mock как факт | запрещено базой | запрещено базой |
| Production seed | невозможен: seed local-only, CI проверяет, deploy не применяет | |

Попытка записать mock-строку с видом `verified_fact` **отклоняется CHECK-ограничением базы**,
а не проверкой в коде.

## 6. Что реально работает

Настоящая база Postgres с row level security на 67 тенантных таблицах; настоящая
авторизация; server actions с проверкой Origin; детерминированное доменное ядро (Margin
Shield, симулятор, entitlements) целиком на сервере; Growth Contract с неизменяемым снимком
и хешем; QR-лояльность с хешированными токенами, раздельными согласиями и идемпотентным
журналом; mini-CRM с курсорной пагинацией; каталог с пятью фильтрами и избранным; Campaign
Studio из семи шагов с сохранением черновика на сервере; двуязычный контент-пак; outbox с
ретраями и dead letter; аварийная остановка; Impact Ledger, разделяющий влияние и прирост;
Admin Console с тремя независимыми рубежами доступа и append-only аудитом; версионирование
шаблонов с настоящей неизменяемостью; тарифы как данные; страница приватности, генерируемая
из схемы; серверное определение локали RU/KK.

## 7. Что симулируется

Отправка сообщений (нет подключённого канала — запуск помечается `SIMULATED` в DEMO_MODE и
отклоняется в PRODUCTION_MODE); отклики на кампанию (18 доставлено / 15 открыто / 9 погашено
— это `demo_time_jump`, каждая строка `is_mock`); результаты кампании (`mock_actual`,
`influenced`, `incremental_estimate` — но никогда `verified_fact`); проверка личности при
вступлении по QR (в демо-режиме помечена `SIMULATED VERIFICATION`); свежая проверка
администратора (осознанный клик подтверждения, а не повторный ввод пароля — баннер говорит
об этом прямо).

## 8. Команды воспроизведения

```bash
# полная установка с нуля
rm -rf node_modules .next && npm ci
npx supabase start
cp .env.example .env.local     # значения из `npx supabase status`

# статические проверки, unit и сборка
npm run verify

# база: реплей всех миграций + pgTAP
npm run db:test

# продакшн-сервер для остальных наборов
npm run build
QADAM_JOB_SECRET=local-dev-job-secret-value \
QADAM_WEBHOOK_SECRET=local-dev-webhook-secret npm start

# полный release audit: seed → E2E → security → a11y → perf → режимы → demo → гейты
npm run test:release
```

Отдельные наборы: `npm run test:e2e`, `npm run test:security`, `npm run test:a11y`,
`npm run test:perf`, `npm run test:modes`.
