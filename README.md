# QADAM Growth OS

AI-маркетолог для малого офлайн-бизнеса в Казахстане: кофеен, салонов, магазинов и точек услуг.
Принцип — **от сигнала и проблемы к прибыльному действию за одно подтверждение**.

Продукт работает на настоящей базе: Postgres с row level security, настоящая авторизация,
настоящие server actions. Демонстрационные данные помечены как демонстрационные и никогда
не выдаются за факт.

## Развёрнутый стенд

| Ссылка | Что это |
|---|---|
| https://qadam-demo.vercel.app | Одно приложение, в котором можно попробовать **и** демонстрационное заведение, **и** боевое |

На `/login` кнопка «Войти в DEMO_MODE» открывает заполненную кофейню TAMYR —
это заведение с `mode='demo'`. Регистрация через `/signup` создаёт **боевое**
заведение в той же базе: демо-входа для него нет, скачка во времени нет,
запуск кампании без подключённого канала отклоняется.

Разделение проходит **по заведениям, а не по окружениям**, и держит его база:
констрейнт `(mode='demo' and is_mock) or (mode='production' and not is_mock)`
и триггер «mock rows are forbidden in production businesses». Синтетическая
строка физически не может попасть в боевое заведение.

**Статус: RELEASE_CANDIDATE технически, EXTERNALLY_BLOCKED для боевого запуска.**
676 автоматических проверок проходят на чистом воспроизведении. Всё, что зависит только от
нас, сделано; платёжный договор, доступ к каналам, юрист, носитель казахского и хостинг —
нет, и это не имитируется. Подробности: [FINAL_ACCEPTANCE](docs/qadam/FINAL_ACCEPTANCE.md)
и [KNOWN_LIMITATIONS](docs/qadam/KNOWN_LIMITATIONS.md).

## Что нужно для запуска

| Требование | Версия | Зачем |
|---|---|---|
| Node.js | 24 или новее | Сборка и тесты |
| Docker Desktop | запущен | В нём поднимается локальный Supabase |
| Supabase CLI | 2.110 или новее | Миграции, seed, pgTAP |

## Запуск одной командой

```bash
npm ci
npm run dev:all
```

Запустите Docker Desktop заранее — в нём живёт локальный Supabase. Дальше `dev:all` делает
всё сам:

1. проверяет Docker и объясняет, что делать, если он не запущен;
2. поднимает Supabase, если он ещё не поднят (если поднят — использует его, это быстрее);
3. синхронизирует `.env.local` с ключами этого Supabase и дописывает недостающие
   переменные — ваши собственные значения не трогает;
4. сверяет, все ли миграции применены и на месте ли демо-данные;
5. запускает Next и раз в минуту прогоняет цикл выполнения — без него автоматизации и
   очередь отправки просто стоят, потому что планировщика у проекта нет.

В конце печатает адреса приложения, Supabase Studio и почтовика, а также демо-логины.

| Флаг | Зачем |
|---|---|
| `npm run dev:all -- --reset` | пересоздать базу с нуля и накатить seed заново |
| `npm run dev:all -- --no-jobs` | не гонять цикл выполнения (например, во время прогона тестов) |
| `PORT=3001 npm run dev:all` | занять другой порт |

`Ctrl+C` останавливает приложение и цикл; Supabase остаётся поднятым, чтобы следующий
запуск был быстрым. Остановить его целиком — `npm run dev:stop`.

<details>
<summary>Если нужно поднять всё вручную</summary>

```bash
npm ci
npx supabase start
cp .env.example .env.local
npx supabase status          # перенесите URL и ключи в .env.local
npx supabase db reset --local
npm run dev
```

</details>

`.env.local` не коммитится. `.env.example` содержит только плейсхолдеры — это проверяется
автоматически (`node tests/security/static-scan.mjs`).

## Миграции и seed

```bash
npx supabase db reset --local          # проиграть все миграции с нуля и наложить seed
npx supabase migration new <название>  # создать новую миграцию
npm run db:types > src/types/database.generated.ts   # перегенерировать типы после изменения схемы
npm run check:types-drift              # упадёт, если типы отстали от схемы
```

`supabase/seed.sql` — **только синтетические данные и только для локальной машины**. CI явно
проверяет, что в нём нет продакшн-данных, а deploy-пайплайн его не применяет.

## Демо-доступы

Существуют там, где установка предлагает демонстрационный вход
(`QADAM_DEMO_TENANTS_ENABLED`). Пароль у всех один: `QadamLocal!2026`.

| Логин | Роль |
|---|---|
| `owner@qadam.local` | владелец демо-заведения TAMYR Coffee |
| `marketer@qadam.local` | маркетолог того же заведения |
| `viewer@qadam.local` | наблюдатель |
| `tenant-b@qadam.local` | владелец **боевого** заведения Tenant B: изоляция и разделение режимов |
| `nomember@qadam.local` | пользователь без членства |
| `admin@qadam.local` | платформенный администратор |

На `/login` есть кнопка «Войти в DEMO_MODE» — она входит владельцем TAMYR Coffee, и никаких
логинов вводить не нужно. Если установка запрещает демонстрационные заведения, кнопки нет, а
server action отказывает, даже если вызвать её напрямую.

Демонстрационный стенд возвращается к исходным данным двумя командами — прогон приёмочных
наборов делает это сам:

```bash
SUPABASE_ACCESS_TOKEN=sbp_... node scripts/apply-remote-sql.mjs <ref> supabase/seed/remote_demo_reset.sql
SUPABASE_ACCESS_TOKEN=sbp_... node scripts/apply-remote-sql.mjs <ref> supabase/seed/remote_demo_seed.sql
```

## Команды тестирования

| Команда | Что проверяет |
|---|---|
| `npm run verify` | lint, типы, unit, разметка, секреты, слой данных, дрейф типов, сборка |
| `npm test` | доменные unit-тесты |
| `npm run db:test` | сброс базы + pgTAP-проверки схемы, RLS и governance |
| `npm run test:e2e` | браузерные сценарии владельца, клиента и администратора |
| `npm run test:security` | RLS-матрица по всем тенантным таблицам, статический скан, HTTP-сьют |
| `npm run test:a11y` | axe-core WCAG 2.1 AA, клавиатура, контраст, адаптивность, скриншоты |
| `npm run test:perf` | бандл, тайминги, запросы, нагрузочный тест, поведение при сбое |
| `npm run test:modes` | разделение демо- и боевого заведения **на одном сервере** |
| `npm run test:release` | полный release audit: seed → E2E → security → a11y → perf → режимы → demo → гейты G1–G12 |

Наборы можно направить на развёрнутый стенд, а не на локальную сборку. Тогда проверки,
которые доказывают утверждения интерфейса строкой в базе, идут через Management API, а
база стенда перед прогоном возвращается к seed:

```bash
export SUPABASE_ACCESS_TOKEN=sbp_...
export QADAM_SUPABASE_PROJECT_REF=<ref демо-проекта>
QADAM_E2E_BASE=https://qadam-demo.vercel.app npm run test:e2e
```

E2E, security и a11y против **локальной** сборки требуют запущенного продакшн-сервера:

```bash
npm run build
QADAM_JOB_SECRET=local-dev-job-secret-value \
QADAM_WEBHOOK_SECRET=local-dev-webhook-secret \
npm start
```

## Языки

Локаль определяется **на сервере** до первого рендера: cookie → сохранённая локаль
пользователя → `Accept-Language` → русский. Лендинг, авторизация, тарифы и оболочка кабинета
двуязычны. Тексты внутри экранов кабинета пока на русском, и интерфейс сообщает об этом
на казахском — перевод ждёт проверки носителем языка.

## Режимы

Режим — свойство **заведения**, а не установки. Колонка `public.businesses.mode`
принимает `demo` или `production`, и база это держит.

- **`mode='demo'`** — разрешены синтетические данные, симулированные запуски и
  скачок во времени. Каждая такая строка помечена `is_mock`, и база не даёт
  назвать её проверенным фактом.
- **`mode='production'`** — демо-фикстуры и симуляции запрещены. Канал без
  подтверждённой проверки связи не станет `connected`, а запуск без
  подключённого провайдера будет отклонён, а не показан как успешный. Попытка
  записать `is_mock`-строку отвергается триггером.

Оба рода заведений живут в одной базе и обслуживаются одной сборкой.
`QADAM_DEMO_TENANTS_ENABLED` — потолок установки: предлагать ли
демонстрационный вход и маршрут `/demo`. Поблажек боевому заведению он не даёт.

## Внешние блокеры

Их не обходят и не имитируют — они перечислены как есть.

| Блокер | Следствие |
|---|---|
| Нет платёжного провайдера | Live billing **BLOCKED**. Checkout отказывает в обоих режимах |
| Нет sandbox-доступа к WhatsApp/Telegram/Instagram | Ни один канал не может дойти до `connected`; `verified_fact` невозможен |
| Нет юридической проверки для Казахстана | Release gate. Указано на самой странице `/privacy` |
| Нет удалённого проекта Supabase | Процедура восстановления из бэкапа описана, но ни разу не выполнялась |
| Нет платформенного планировщика | Цикл выполнения запускает внешний вызов `/api/jobs/run-cycle` с секретом |
| Нет носителя казахского языка в ревью | Каждый KK-материал помечен `native_review_required` |

## AI-провайдер

По умолчанию `QADAM_AI_PROVIDER=none`, и генератор работает на встроенном детерминированном
шаблоне. Это поддерживаемое состояние: интерфейс прямо пишет владельцу, что текст собран
шаблоном, а не моделью.

При подключённом провайдере (`anthropic`, `openai` или `gemini`) работает тот же контракт: строгая
проверка схемы ответа, ограничение по стоимости и времени, ограниченное число повторов и
детерминированный откат при любой ошибке. **PII и секреты в провайдер не уходят**, а решение
Margin Shield принимает сервер — модель не может его обойти.
